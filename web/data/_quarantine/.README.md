# Quarantined data files

Files here are invalid JSON, pulled out of `web/data/` so a corpus-wide JSON
glob (search index build, content loader, etc.) doesn't throw on them.

## article-content-patch-11.json / article-content-patch-12.json

**Defect:** literal unescaped `"` characters inside a JSON string value —
a direct quotation embedded in the article HTML (e.g. `"the ruling is based
on the generality of the wording..."`) was never escaped as `\"`. Same
defect class in both files, at the first quoted phrase in each.

- patch-11: `Expecting ',' delimiter: line 10 column 4173 (char 22810)`
- patch-12: `Expecting ',' delimiter: line 12 column 786 (char 23015)`

**Why quarantined instead of fixed:** both files are already superseded.
`scripts/articles/merge-article-patches.ts` globs
`article-content-patch-*.json` in `web/data/articles/`, which matches these
AND their `-fix.json` siblings (`article-content-patch-11-fix.json`,
`article-content-patch-12-fix.json`, still in place). The merge script
catches `JSON.parse` failures per file and just logs and continues, so these
two broken originals were already being silently skipped — the `-fix`
files (which parse cleanly and contain the same 20 article slugs each) are
the ones actually reaching `articles.json`. Hand-patching the quote
escaping here would produce a second, independently-maintained copy of
prose that already has a working canonical version; that's a content-drift
risk, not a fix. No article content is lost by moving these out — nothing
in `scripts/` or `web/` referenced them by exact filename before this move,
only via the `article-content-patch-*` glob, and the glob still picks up
the `-fix` versions.

**If revisited:** confirm `-fix.json` still fully supersedes (same slug set,
newer or equal content), then delete these instead of leaving them
quarantined.

## death-of-the-prophet.json

Not quarantined — this one was fixed directly (see git history). Recorded
here only because it was found in the same sweep.

**Defect:** the `narrative` field contained a direct quotation
(`He said: "With the highest companion, with the highest companion,"`) with
literal unescaped `"` — the same defect class as the two files above, but
here it was a single unambiguous instance with no other copy of the
content anywhere else in the repo, so the mechanical fix (escape the two
quote marks as `\"`) was applied in place. No wording was changed.
